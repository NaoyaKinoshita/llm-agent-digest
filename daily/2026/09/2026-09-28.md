## 3. LLM Model / AI Agentアーキテクチャ・研究

### 3.1 論文、コード化されたスキルによるエージェントの行動抽象化を検証

プリンストン大学のKarthik R. Narasimhan氏(ReAct・SWE-agent等で知られる)、ワルシャワ大学/IDEAS NCBRのBartłomiej Cupiał氏・Maciej Wołczyk氏ら、Carnegie Mellon大学のBenjamin Eysenbach氏、MilaのMartin Klissarov氏らの共同研究チームは9月25日、論文「Up and Down the Abstraction Ladder: Code-Based Skills for Language Agents」を発表した(arXiv公開は9月28日バッチ)。ゲームや長時間の業務操作のように、低レベルな行動を延々と積み重ねる必要があるタスクでは、LLMエージェントが逐一プリミティブな行動を選択する方式は非効率であるという課題があった。

研究チームは、自然言語による説明を付けた再利用可能な関数「コードベースのスキル」をエージェントに与え、プリミティブのみで行動する方式、スキルのみで行動する方式、状況に応じて両者を行き来するハイブリッド方式を比較するため、長時間ホライズンの高難度ゲーム環境NetHack向けのスキルライブラリ「CodeHack」を構築した。評価の結果、スキルベースのエージェントはプリミティブのみのエージェントに対しゲーム進行度を約3倍に高めつつ、LLMによる意思決定回数の減少により1エピソードあたりの推論コストを約86%削減した。ハーネス設計(行動空間の抽象化レベル)自体がエージェントアーキテクチャ上の重要な設計判断であることを定量的に示した点が特徴である。[[1]](#ref-1)

```mermaid
sequenceDiagram
    participant LLM as "LLMエージェント"
    participant Ladder as "抽象化ラダー(CodeHackスキルライブラリ)"
    participant Env as "NetHack環境"

    LLM->>Ladder: "状況に応じてスキル利用かプリミティブ実行かを判断"
    Ladder->>Env: "コード化されたスキルで複数ステップの行動をまとめて実行"
    Env-->>LLM: "圧縮された観測結果を返却し意思決定回数を削減"
    Note over LLM,Env: "ゲーム進行度を約3倍に向上、推論コストを約86%削減"
```

### 3.2 論文、マルチエージェント協調のテスト時計画手法「MA-WAM」を提案

中国・中山大学(Sun Yat-sen University)のGuowei Zou氏、Haitao Wang氏らは9月25日、論文「MA-WAM: Multi-Agent World-Action Model for Test-Time Planning」を発表した。複数エージェントが協調するタスクでは各エージェントの行動が同時に他エージェントの観測・結果に影響を与えるため、単一エージェント向けの世界モデルをそのまま個別適用しても、エージェント間の依存関係をチーム全体の報酬予測に反映できないという課題があった。

提案手法「MA-WAM」は、あらかじめ学習済みの固定されたマルチエージェント方策が複数の候補となる同時行動系列を提案し、「Routed World Model(RWM)」と呼ぶ経路づけされた世界モデルがエージェント間の依存関係を明示的にモデル化して各候補のチーム報酬を予測、最良のものを選択したうえで次の観測から再計画するという、モデル予測制御(MPC)的なループを回す。方策自体を再学習せずテスト時のプランニングのみで性能を引き上げられる点が特徴で、単一エージェント向けのテスト時探索(MCTS等)をマルチエージェント設定に拡張した枠組みと位置づけられる。[[2]](#ref-2)

```mermaid
sequenceDiagram
    participant Policy as "固定済みマルチエージェント方策"
    participant RWM as "Routed World Model(RWM)"
    participant Planner as "プランナー"
    participant Env as "マルチエージェント環境"

    Policy->>RWM: "複数の同時行動系列候補を提案"
    RWM->>Planner: "エージェント間依存関係を踏まえチーム報酬を予測"
    Planner->>Env: "最良の同時行動を選択し実行"
    Env-->>Policy: "新たな同時観測を取得し再計画(MPC的ループ)"
```

### 3.3 論文、大脳皮質の情報ルーティングに着想した「Programs-of-Layers」を再現実験、主要な主張の再現に失敗

ドイツ・ベルリン技術大学(Berliner Hochschule für Technik)のJustus Westerhoff氏、Stephan Olbrich氏、Hatem Oraby氏、Matthew Evan Larkum氏、Felix Alexander Gers氏は9月25日、論文「Programs-of-Layers in LLMs through the Lens of Cortical Areas」を発表した。通常のLLM推論は入力の難易度によらず全レイヤーを固定順序・固定深度で通過するのに対し、人間の脳は視床を中枢ハブとして大脳皮質の各領域へ需要に応じ柔軟に情報を経路づけている。この類推から、先行研究(Li et al., 2026)はTransformerのレイヤーを固定順序の列ではなく「関数のライブラリ」とみなし、入力ごとにレイヤーブロックの省略・繰り返しを動的に組み合わせる「Program-of-Layers(PoLar)」を提案していた。

本論文はPoLarの診断用モンテカルロ木探索(MCTS)手順を5種類のLLMに対しより詳細に再構築して再現実験を行った。その結果、レイヤーの省略・繰り返しを組み合わせた「プログラム」群を上位k個(top-k)としてまとめて評価した場合には精度向上が確認できた一方、学習済みルーターが単発推論で選ぶ最上位(top-1)の予測は一貫して標準的な全レイヤー通過に収束してしまい、原論文が主張する学習済みルーター自体の有効性は再現できなかったと報告している。さらに、少数の汎用的な「プログラム」だけで大半の設問に対応できてしまうこと、誤り訂正用のプログラムは非常に壊れやすく内部の一手順を変えるだけで訂正効果が失われることも判明した。都合の良い結果だけでなく再現の失敗も含めて報告した点で、LLMアーキテクチャ研究の再現性を考えるうえで示唆に富む。[[3]](#ref-3)

```mermaid
sequenceDiagram
    participant Input as "入力(難易度は様々)"
    participant Router as "学習済みルーター(視床的ハブに着想)"
    participant Layers as "Transformerレイヤー群(省略/繰り返し可能)"
    participant Eval as "再現実験(5種のLLMでMCTS手順を再構築)"

    Input->>Router: "難易度に応じたレイヤー実行プログラムの選択を要求"
    Router->>Layers: "top-1予測は標準の全レイヤー通過に収束(再現失敗)"
    Eval->>Layers: "top-k候補をまとめて評価すると精度向上を確認"
    Note over Router,Eval: "少数の汎用プログラムで大半の設問に対応、誤り訂正プログラムは脆弱"
```

### 4.1 Anthropic、高速・低コストな新モデル「Claude Sonnet 5.5」を発表

Anthropicは9月28日、Claude 5.5ファミリーの第2弾となる新モデル「Claude Sonnet 5.5」を発表した。9月22日発表の最上位モデルClaude Opus 5.5を補完する位置づけで、バグ修正や資料・スライド・スプレッドシート作成など範囲が明確な日常業務、デザイン面での判断力、画像理解を伴う長時間タスクに強みを持つとされ、スクリーンショットのみからポケットモンスター赤を攻略できた初のSonnetモデルだとしている。ベンチマークでは、エージェント型コーディング評価Terminal-Bench 4.0でClaude Sonnet 5の10.3%から70.6%へと大幅に向上したほか、知識労働評価GDPval-AA v2.1でスコア1844(Opus 5.5の1846にほぼ匹敵)、コンピュータ操作評価OSWorld 2.1で80.1%、図表読解評価Chartographyで61.6%を記録した。

価格はClaude Sonnet 5と同水準(入力100万トークンあたり2ドル、出力同10ドル、キャッシュ読み込み同0.20ドル)に据え置きつつ、必要トークン数・ツール呼び出し回数の削減により出力速度は30%以上高速化、タスクあたりのコストは最大30%削減されるとしている。安全面では、Sonnet系として初めてOpus 5.5に匹敵するサイバーセキュリティ対策を実装したほか、モデルの推論過程の抽出(蒸留)を防ぐ分類器や「保持された思考(preserved thinking)」機能を拡張し、生物学的リスクに関する安全策はSonnet 5と同水準を維持。責任スケーリングポリシー(RSP)評価では、Opus 5.5より総じて能力は低く新たな閾値は超えていないとし、無許可の境界の探索や監視をすり抜けるサンドボックス脱出の試行率が評価対象モデルの中で最も低いなど、誤動作(ミスアライメント)リスクは低いと評価したという。AWS・Google Cloud・Microsoft Azureを含む全プラットフォームでモデルID「claude-sonnet-5-5」として提供が始まっている。[[4]](#ref-4) [[5]](#ref-5)

```mermaid

    Dev->>Opus55: "複雑な判断はOpus 5.5、日常タスクはSonnet 5.5へ使い分け"

```
